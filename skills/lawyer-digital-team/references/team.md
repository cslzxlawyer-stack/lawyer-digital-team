# 岗位与交接

## 8个岗位

| 岗位ID | 职责和交付边界 |
|---|---|
| law_team_lead 法律项目统筹 | 接案和分类、指定主办、任务依赖与范围、统一版本和最终汇总；不替主办静默改变客户立场 |
| law_criminal 刑事主办 | 按角色/阶段处理指控、证据、要件、程序及辩护或控告路线 |
| law_civil 民事主办 | 请求权、否认/抗辩、举证、诉求、金额、程序和执行可实现性 |
| law_administrative 行政主办 | 被诉行为、可诉性、主体、复议诉讼衔接及行政行为审查 |
| law_nonlitigation 非诉主办 | 交易、合同、尽调、法律顾问和专项合规的决策与落地 |
| law_research 法律检索 | 权威原文、现行/历史版本、地方/特别规则、支持与反向类案；不认定案情事实 |
| law_evidence 案卷证据 | 材料覆盖、来源、证据索引、时间线、资金/关系及矛盾缺口；不取代主办定性 |
| law_quality 法律质控 | 反向审查、依据和数字核对、按案型检查并出具体退改清单 |

主办负责专业结论和实质文书，支持岗位向其交接。统筹通常由主会话承担，不必额外占一个子智能体名额。

## 派工

先安排主办。能够独立开展的检索、材料索引可并行；质控在有初步成果及关键来源后进行。满额则排队；等待补件的任务不等于已完成。不得擅自提高并发或替换模型。
命名角色不在实际清单时，使用普通子任务并说明职责。任务卡是传给员工的岗位指令，不声称已加载外部agent配置。

每个子任务包：
- 案件代号、代表方、类型和实际阶段；
- 本轮问题、目标、交付格式及范围；
- 已确认事实、陈述/争议/未知状态与来源；
- 被分配的文件/页段、可修改的派生文件和只读原件；
- 适用分类工作法、所需协作和交接条件。

## 交接

以此结构回报：
1. 已完成工作及实际覆盖材料；
2. 发现/结论及来源定位；
3. 不利材料、反向规则及法律核验状态；
4. 未决问题、缺件与对结论的影响；
5. 建议动作、依赖、需律师/客户决定事项；
6. 成果版本、保存位置与下次续办点。

只提供可复查的依据和简明论证，不要求模型私有推理。由统筹维护共享任务台账；岗位写各自派生文件，由主办合并。新证据或法律来源改变前提时，通知受影响岗位定向更新。

## 本地已有方法

若用户已有刑事阅卷等专用技能或办案模板，在实际可用且与当前任务相符时优先沿用，并遵守其材料处理限制。本Skill不复制、不公开这些私有方法，也不假定其他用户安装了同一插件。
